# 11. 非機能要件

## 11.1 ネットワーク・外部依存

- フロントエンドはCloudflare Pages経由でHTTPS配信される。
- バックエンドはPython 3.14 + FastAPIのアプリケーションコンテナとしてVPS上でホストされ、VPSホストのnginxからHTTPS通信を受け付ける。
- 外部CDN、単語辞書サービス、外部フォント配信サービスは使用しない。
- フォントには Noto Sans JP を採用し、フォントファイル、Vue、Vuetify、Vite などの依存関係はビルド時にバンドル（セルフホスト）して配信する。外部CDNからの動的読み込みは行わない。

## 11.2 ブラウザ互換性

- PCを対象とする。
- Android 10以降のスマートフォン・タブレットを対象とする。
- iOS/iPadOSのスマートフォン・タブレットを対象とする。
- `localStorage`、タイマーAPI、`crypto.getRandomValues`、`EventSource` API、Touch Eventsを利用する。画面の描画とイベント処理はVue 3のコンポーネントで行う。
- レスポンシブデザインにより、画面幅に応じてレイアウトを変更する。

## 11.3 性能

- 設定画面の表示から操作可能になるまで、外部読み込み待ちを発生させない。
- 単語確定後の全カード更新とビンゴ再計算を、通常のレクリエーション規模で体感遅延なく完了させる。
- `N×N`カードの更新は、カードごとの`N×N`マスを走査する単純な処理で実装する。
- タイマー更新でゲーム状態全体を再構築せず、残り時間表示だけを更新する。
- 画面描画は、入力中のプレビューと単語確定後の状態更新を分離する。

## 11.4 データ保存・プライバシー

### フロントエンド保存

- 保存先は同一ブラウザの`localStorage`とする。
- 保存単位は利用者が明示的に作成した名前付き設定プリセットとする。
- プリセットはゲームルール設定だけで構成し、ゲーム進行の信頼性には影響させない。
- `localStorage`の値が壊れている場合は該当プリセットを読み込まず、初期設定を表示する。

### バックエンド保存

- ゲーム進行状況、カード状態、単語履歴、undoスナップショットはサーバーのSQLiteに保存する。
- 最後の接続が切断され、30分間再接続も新しい接続もない`setup`または`result`状態のルームは自動削除する。また、フェーズや接続の有無にかかわらず、作成または最終更新から24時間が経過したルーム（`playing`状態を含む）はサーバーにより強制削除する。
- パスワードは平文で保存せず、bcryptでハッシュ化して保存する。
- IPアドレスはプレイヤー識別子に使用しない。運用上必要なIPアドレスの記録はVPSのnginxアクセスログで行い、アプリケーションのプレイヤー情報には原則として取り込まない。

### 通信

- 本番環境ではHTTPS通信を使用し、平文HTTPのAPIを受け付けない。ローカル開発では`http://localhost:3001`を使用する。
- アクセス解析、外部ログ送信を行わない。

## 11.5 セキュリティ

### XSS対策

- プレイヤー名、単語履歴、エラーメッセージをHTMLとして解釈しない。
- 利用者入力を`innerHTML`、`eval`、動的なスクリプトとして使用しない。
- Vueの通常のテキストバインディングで安全に表示し、`v-html`は使用しない。
- `localStorage`から読んだ値も未信頼入力として扱う。
- サーバーから受信したJSONも未信頼として扱い、必要に応じてエスケープする。

### 通信セキュリティ

- 本番APIはHTTPSのみ受け付ける。再接続Cookieには`HttpOnly`、`Secure`属性を付ける。
- ルームIDは推測困難なランダム文字列（16文字以上のURL-safe文字列）とする。
- パスワードはbcryptでハッシュ化し、認証時に比較する。
- SSE接続はルームIDと再接続Cookieを使用して認証し、該当ルームの配信ストリームに接続する。他ルームの情報は漏洩しない。Cloudflare Pagesからの接続ではCookie付きCORSを使用し、許可オリジンを限定する。
- 操作権限（現在の手番プレイヤーだけが単語を入力可能、親だけが管理操作可能）は、サーバー側でリクエストの正当性を検証する。手番外の入力リクエストは拒否する。

### シークレット管理

- 外部サービスへの認証情報や秘密情報は環境変数またはDocker secretsで管理し、ソースコードに含めない。

## 11.6 アクセシビリティ

- フォーム項目に明確なラベルを付ける。
- キーボードだけで設定、単語確定、undo、新しいゲームを操作できるようにする。
- スマートフォンではタッチ操作がしやすいサイズ（最小44×44pxのタッチターゲット）を確保する。
- 入力欄はモバイル端末で適切なキーボードタイプ（テキスト入力）が表示されるようにする。
- 色以外の視覚表現を併用する。
- フォーカス位置が見えるようにする。
- エラーと現在の開始文字をテキストで表示する。
- フォントには Noto Sans JP を使用し、濁音・半濁音や小さい文字（拗音・促音）を含めて高い視認性と判読性を確保する。

## 11.7 信頼性

- 不正な単語入力でTypeScriptエラーを発生させず、エラー表示または無効入力処理へ進む。
- タイマーが0秒になっても、ゲーム状態を壊さず入力を継続できる。
- undoで、マス、ビンゴ数、履歴、手番、開始文字、失格状態、制限時間を一貫して戻す。
- ページ再読み込み時は、ルームIDがURLに含まれていれば再接続Cookieで同じプレイヤーとして再接続し、最新状態をSSEで受信する。
- 終了条件、ビンゴ数、順位の計算を画面表示だけでなくサーバーのゲーム状態から再現できるようにする。

### 通信エラー時の復旧

- SSE接続が切断された場合、指数バックオフで自動再接続を試行する。ロビー・結果画面では切断から30分以内、対戦中はゲームが結果状態へ移るまで再接続を受け付ける。再接続後は最新の公開用GameState全体を受信する。
- POST送信が失敗した場合、エラーメッセージを表示し、親が再試行できるようにする。
- サーバーが一時的に停止した場合、ページ再読み込みで再接続を試みる。

## 11.8 保守性

### フロントエンド

- Vueコンポーネントで設定、文字処理、ゲーム表示、イベント処理を論理的に分離する。
- Piniaストアでゲーム状態と通信状態を集中管理する。
- 文字の候補集合と語尾正規化表は定数としてまとめる。
- ビンゴ列の座標は、カードサイズ`N`から横列、縦列、斜め列を生成する。

### バックエンド

- FastAPIのルーターでAPIエンドポイントを分離する。
- ゲームエンジン（ロジック層）とHTTP層を分離する。
- SQLiteアクセスは専用のDAO/リポジトリ層で抽象化する。
- SSE配信は専用のブロードキャストモジュールで管理する。

### 共通

- 仕様にないゲームルールを暗黙に追加しない。
