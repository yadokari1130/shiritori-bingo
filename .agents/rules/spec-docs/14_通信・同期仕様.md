# 14. 通信・同期仕様

## 14.1 通信方式

クライアントとサーバーの通信は、次の2方式を組み合わせる。

| 方式 | 方向 | 用途 |
| --- | --- | --- |
| HTTP POST/PUT | クライアント→サーバー | ロビー作成、参加、チーム選択、未所属者のランダム配置、設定変更、ゲーム開始、単語確定、undo、スキップ |
| SSE（Server-Sent Events） | サーバー→クライアント | ゲーム状態のリアルタイム同期 |

## 14.2 APIエンドポイント

### POST /api/rooms

ルームを作成する。親がトップ画面で「ルームを作成」を押した時に呼ぶ。作成直後のルームは`setup`状態で、プレイヤーとカードは未生成とする。ルール設定は作成後もロビーで変更できる。

**リクエストボディ**

```json
{
  "settings": { /* ルール設定オブジェクト */ },
  "password": "string | null"
}
```

**レスポンス200**

```json
{
  "roomId": "abc123xyz789",
  "url": "https://example.com/game/abc123xyz789",
  "gameState": { /* setup状態のGameState */ }
}
```

### POST /api/rooms/:roomId/join

ルームに参加する。参加者がロビーまたはトップ画面で「参加」を押した時に呼ぶ。専用URLを直接開いた場合も、ロビーで名前を入力して同じAPIを呼ぶ。有効な再接続Cookieがある場合は、Cookieに紐付く既存のプレイヤーを復帰させる。

**リクエストボディ**

```json
{
  "password": "string | null",
  "name": "string"
}
```

**レスポンス200**

```json
{
  "gameState": { /* 現在のGameState */ },
  "playerId": "string",
  "isHost": "boolean"
}
```

レスポンスには、再接続用の不透明なトークンを`HttpOnly`、`Secure`属性付きCookieとして設定する。サーバーはCookieのハッシュだけを保存し、Cookieの値をゲーム状態や画面へ配信しない。ロビー・結果画面では切断から30分以内、対戦中は結果状態へ移るまで、同じCookieによる参加者復帰を受け付ける。

チーム戦では、参加リクエスト後に参加者自身が所属チームを選択できる。チーム選択の変更はロビー状態としてSSEで全参加者へ配信する。

**エラーレスポンス**

- 400: 名前が空文字、またはJSON形式・リクエスト項目が不正
- 404: ルームが存在しない
- 403: パスワードが違う
- `result`状態では有効な再接続Cookieを持つ既存参加者だけが結果画面へ復帰できる
- 親が`setup`へ戻した後は、同じルームのロビーへ新しい参加者が参加できる

### PUT /api/rooms/:roomId/name

ロビーで、リクエスト元の参加者自身の名前を変更する。`setup`状態でのみ呼び出せ、空文字の名前は拒否する。重複名、文字数、使用文字については制限しない。成功時は更新後の`setup`状態を返し、全クライアントへSSEで配信する。

**リクエストボディ**

```json
{
  "name": "string"
}
```

**エラーレスポンス**

- 400: 名前が空文字、またはJSON形式・リクエスト項目が不正
- 403: 有効な参加者Cookieがない、またはゲーム中・結果画面での変更

### GET /api/rooms/:roomId

専用URLを表示する前にルームの存在を確認する。ルームが存在する場合はフェーズとパスワード設定の有無を返し、存在しない場合は404を返す。

### POST /api/rooms/:roomId/start

ロビーのゲームを開始する。現在の親プレイヤーに紐付く再接続Cookieだけが呼び出せ、参加者が2人未満の場合、またはチーム戦で所属人数が0人のチームが存在する場合は開始できない。成功時に`playing`状態を返し、全クライアントへSSEで配信する。

### POST /api/rooms/:roomId/leave

ロビーから明示的に退出する。ページ離脱時の補助通知として呼び出し、明示的な退出では直ちにプレイヤー削除、親移譲、空ルーム削除を行う。通信切断だけの場合は、SSE切断処理の30分間の復帰猶予を適用する。

### PUT /api/rooms/:roomId/settings

ロビーのルール設定を変更する。親だけが呼び出せ、ゲーム開始後は変更できない。成功時に更新後の`setup`状態を返し、全クライアントへSSEで配信する。

### POST /api/rooms/:roomId/lobby

ゲーム終了後に同じルームをロビーへ戻す。親だけが呼び出せ、カード、単語履歴、手番状態を初期化して`setup`状態を返す。結果状態の間は、参加者全員が結果画面を表示する。

### POST /api/rooms/:roomId/host

ロビーで親が接続中の参加者を指定して親を変更する。現在の親だけが呼び出せ、指定された参加者を新しい親にし、元の親を通常の参加者として扱う。変更後の状態と親変更通知を全クライアントへSSEで配信する。

### PUT /api/rooms/:roomId/team

チーム戦のロビーで、参加者自身が所属チームを変更する。対象の参加者CookieとチームIDを検証し、個人戦中またはゲーム開始後の変更は拒否する。

### POST /api/rooms/:roomId/teams/randomize

親が未所属の参加者をチーム間の人数差が1以内になるようランダムに割り当てる。既に所属チームを選択した参加者は変更しない。更新後のロビー状態をSSEで配信する。

### POST /api/rooms/:roomId/action

ゲーム操作を送信する。単語確定は個人戦では現在の手番プレイヤー、チーム戦では現在チームの所属者だけが呼べる。スキップ、失格、undoは親だけが呼べる。親によるスキップ・失格は現在手番のプレイヤーまたはチームに対してのみ実行できる。設定に応じた無効入力のスキップ・失格と、時間切れ時の強制スキップはサーバーが自動的に適用する。

**リクエストボディ**

```json
{
  "type": "word",
  "word": "string"
}
```

`skip`、`disqualify`、`undo`は操作ごとに異なるリクエスト型を使用する。

```json
{ "type": "skip", "subjectId": "string" }
```

```json
{ "type": "disqualify", "subjectId": "string" }
```

```json
{ "type": "undo" }
```

`subjectId`は個人戦ではプレイヤーID、チーム戦ではチームIDとする（現在手番のIDと一致している必要がある）。

**レスポンス200**

```json
{
  "success": true,
  "gameState": { /* 更新後のGameState */ }
}
```

**エラーレスポンス**

- 400: JSON形式またはリクエスト項目が不正（空文字やひらがな・伸ばし棒以外の単語送信、現在手番外に対するskip/disqualifyを含む。手番は維持される）
- 403: 操作対象外のプレイヤーからのリクエスト
- 409: ゲーム状態が既に変わっている（競合）
- `word`操作でしりとり不成立、語尾が`ん`、重複単語などになった場合は、設定に応じた処理を適用した更新済み`gameState`を200で返す。全員失格となった場合は即時で`result`状態へ移行した`gameState`を返す。
- `result`状態での`undo`操作は409で拒否する。

### GET /api/rooms/:roomId/events

SSE接続エンドポイント。ルームIDと再接続Cookieを検証し、認証済みの参加者へゲーム状態変更イベントを配信する。

- `Content-Type: text/event-stream`
- Cloudflare Pagesから接続する場合はCookieを送信する設定でEventSourceを確立し、API側は許可済みオリジンに対して資格情報付きCORSを返す。
- 接続確立時に現在の`gameState`を`initial`イベントで送信する。
- 以降、状態変更ごとに`update`イベントを送信する。

## 14.3 SSEイベント形式

### イベント種別

| イベント名 | 内容 |
| --- | --- |
| `initial` | 接続確立時の現在状態。公開用GameStateと結果情報を含む。再接続Cookie、セッション情報、undoスナップショットの内部データは含めない。 |
| `update` | 最新の公開用GameState全体。操作後または親変更後に配信。 |
| `error` | サーバー側エラー。クライアントは再接続を試行する。 |
| `ping` | 30秒間隔のハートビート。接続維持用。 |
### イベントデータ形式

```json
{
  "event": "update",
  "timestamp": 1234567890,
  "gameState": { /* GameStateオブジェクト */ },
  "notice": "親が変更されました。"
}
```

## 14.4 操作権限

### 親の判定

- ルーム作成者が最初に参加したプレイヤーを親とし、親の権限は`host_player_id`へ紐付ける。
- ロビーでは現在の親が接続中の参加者を指定して親を変更できる。対戦中および結果画面では手動変更を行わない。
- 親のすべての接続が切断された場合は、接続中の参加者のうち参加登録順で先頭の参加者へ即時に親を移譲する。元の親が再接続しても自動的には親へ戻さない。
- 接続中の参加者がいない場合は親を一時的に未設定とし、次に接続した参加者へ親を移譲する。
- プレイヤーの識別と再接続は、サーバーが発行する`HttpOnly`、`Secure`属性付きCookieで管理する。ユーザーアカウント、ログイン、JWTは使用しない。
- 参加者は現在の手番であれば単語入力と確定を行える。現在の手番ではない参加者は表示のみとする。

### 権限チェック

| 操作 | 親 | 参加者 |
| --- | --- | --- |
| ロビー参加者登録 | ○ | ○ |
| ゲーム開始 | ○（全チーム所属必須） | × |
| 単語確定 | 現在の手番なら○ | 現在の手番、または現在チームのメンバーなら○ |
| スキップ/失格適用 | 現在手番の対象に対してのみ○ | × |
| undo | 対戦中のみ○ | × |
| ロビーでの親変更 | ○ | × |
| ロビーでの自分の名前変更 | ○ | ○ |
| ルーム閲覧（SSE） | ○ | ○ |
| 設定変更 | ○（ロビー中のみ） | × |

## 14.5 接続管理

### SSE接続のライフサイクル

1. クライアントがページを開くと、再接続Cookieを付けてSSE接続を確立する。
2. サーバーはCookieからプレイヤーIDを特定し、接続をルームとプレイヤーに紐づけて状態変更を配信する。
3. クライアントがページを閉じると、接続は自動的に切断される。
4. サーバーは接続数を管理し、すべての接続が切断された時刻を記録する。

### 再接続戦略

- ロビーまたは結果画面の接続切断時は、EventSourceの自動再接続を30分以内の復帰猶予として利用する。30分を過ぎるとプレイヤーを該当状態の参加者から削除する。結果状態では確定済みのResultSnapshotを保持する。
- 対戦中の接続切断時は、ゲームが結果状態へ移るまで再接続を受け付ける。切断中のプレイヤーを自動スキップまたは自動失格にしない。
- 自動再接続は指数バックオフで行い、ロビー・結果画面では切断から30分を超えない範囲で試行する。対戦中は結果状態へ移るまで試行する。
- 再接続後は差分を再送せず、最新の公開用GameState全体を`initial`イベントで送信する。
- フェーズ（`playing`状態を含む）や接続の有無にかかわらず、作成または最終更新から24時間が経過したルームはサーバーにより強制削除される。

## 14.6 エラーハンドリング

### クライアント側

- ネットワークエラー時は「通信エラー」メッセージを表示し、自動再接続を試行する。
- サーバーから400エラーを受信した場合、エラー内容を画面に表示し、入力欄は保持する。ゲームルール上の無効単語は200応答で自動処理される。
- サーバーから403エラーを受信した場合、「操作権限がありません」を表示する。

### サーバー側

- 無効なJSONは400で拒否する。
- 存在しないルームIDは404で拒否する。
- 親以外の操作リクエストは403で拒否する。
- ゲーム状態の競合（同時操作）は409で拒否する（楽観ロック）。
