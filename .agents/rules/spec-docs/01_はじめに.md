# 1. はじめに

## 1.1 背景

しりとりビンゴは、知り合い同士で行うレクリエーションのためのゲームである。通常のビンゴカードには数字を配置するが、本サービスではひらがなを配置し、手番のプレイヤーが入力したしりとりの単語に含まれる文字を全員のカードから開く。

## 1.2 目的

本サービスの目的は、知り合い同士が各自の端末から参加し、手番のプレイヤーがしりとりの単語を入力することで全員のビンゴカードを同時に進行できるようにすることである。通信機能を介してゲーム状態をリアルタイムに同期し、参加者は自分の端末でカードや進行状況を確認できる。

## 1.3 対象利用者

- 知り合い同士のレクリエーション参加者
- ロビーの参加者を管理し、ゲームを開始する親
- 自分の手番で単語を入力するプレイヤー

参加者は各自の端末のブラウザからルームに参加できる。親はロビー設定、ゲーム開始、undoの操作権限を持ち、単語入力は現在の手番プレイヤーだけが行う。1人のプレイヤーは、同じ再接続Cookieを持つ複数タブから同時に接続できる。

## 1.4 対応環境

- PC
- Androidスマートフォン・タブレット
- iOS/iPadOSスマートフォン・タブレット
- フロントエンドはCloudflare Pagesにデプロイされ、HTTPS経由で配信される
- バックエンドはPython 3.14 + FastAPIのアプリケーションコンテナとしてVPS上でホストされ、VPSホストのnginxがHTTPSとリバースプロキシを担当する
- インターネット接続が必要

## 1.5 対象範囲

### 対象に含む機能

- ゲームルールの初期設定とロビー作成
- ロビーでの参加者名設定と参加
- 名前付き設定プリセットのブラウザ`localStorage`保存
- ゲームルームの作成、パスワード保護、URL共有
- 参加者によるルームへのURLアクセスでの参加
- 参加者順のランダム決定
- 奇数サイズ（初期値5×5）のビンゴカードのランダム生成
- 全員共通の中央フリーマス
- しりとりの形式的な接続判定
- 重複単語、語尾、入力文字の判定
- 単語による全カードのマス開放
- ビンゴ列の判定と表示
- 制限時間の表示
- 無効入力時の失格またはターンスキップ
- 直前操作のundo
- ゲーム終了後の同じルームのロビー復帰
- サーバー側でのゲーム状態永続化（SQLite）
- SSEによるリアルタイム状態同期

### 対象外とする機能

- 単語の存在確認、辞書検索、自然言語処理
- 音声認識や自動単語入力
- ユーザーアカウント、認証、ログイン機構
- 外部API、外部辞書サービス、外部CDN（外部フォント配信サービスを含む）
- 名前や単語の意味に基づく評価

## 1.6 固定された前提

- ゲーム開始時の参加者は2人以上とする。参加人数は事前に固定しない。
- 名前は空文字を許可せず、重複や文字数、使用文字についての制限は設けない。名前はロビーで本人が変更できる。
- カードサイズは3以上の奇数とし、初期値を5×5とする。中央のマスをフリーマスとする。
- フリーマスの文字はゲームごとに清音から1文字ランダムに選び、個人戦では全プレイヤー、チーム戦では全チームのカードで同じ文字にする。
- フリーマスはゲーム開始時から開いている。
- フリーマスを含め、同じカード内では同じ文字を重複させない。別のカード間では同じ文字が重複してよい。
- 単語の存在確認は行わず、手番のプレイヤーが有効な単語かを判断する。
- ゲーム中のプレイヤー順は、開始時に決めたランダム順で固定する。
