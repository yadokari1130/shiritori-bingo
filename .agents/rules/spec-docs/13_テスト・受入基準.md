# 13. テスト・受入基準

## 13.1 単体テスト方針

- バックエンドの単体テストにはpytestを使用する。
- フロントエンドの単体テストにはVitestを使用する。
- バックエンドは、しりとり判定、語尾の正規化、カード生成、ビンゴ判定、ターン処理、終了条件、undo、および設定値の検証を、HTTP通信やSQLiteに依存しない単位でテストする。
- フロントエンドは、設定プリセットの読み書き、入力値の検証、表示用状態の変換、画面状態の遷移、および通信イベントの処理を、外部ネットワークに依存しない単位でテストする。
- ルール上の正常系、無効入力、境界値、異常系をテスト対象とし、仕様書の受入基準と矛盾しないことを確認する。
- 単体テストは変更時および受入確認時に実行し、すべて成功することを受入条件とする。
- 実行コマンドは、バックエンドを`uv run --directory backend pytest`、フロントエンドを`pnpm --dir frontend test`とする。

## 13.2 初期設定

| 確認項目 | 受入基準 |
| --- | --- |
| ロビー参加人数 | 2人で開始でき、1人では開始できない。人数を事前設定しない |
| ロビー参加名 | 各参加者がロビー参加時に名前を設定でき、空文字では参加できず、重複名では開始できる |
| ロビー名前変更 | ゲーム開始前のロビーで各参加者が自分の名前を変更でき、空文字では変更できず、変更結果が全参加者へ反映される。ゲーム中と結果画面では変更できない |
| プリセット保存 | 名前を付けた設定プリセットを明示的に保存、読み込み、上書き保存、削除できる |
| トップ画面の文言 | 操作やルール理解に必要な案内だけを自然な日本語で表示し、保存方式や内部状態の注記を表示しない |
| ゲーム状態復帰 | 専用URLを再読み込みすると、再接続Cookieで同じプレイヤーとして最新のゲーム状態へ復帰できる |
| カードサイズ | 3以上の奇数を指定でき、初期値は5である。選択した文字候補数から算出した上限を超える値、偶数、2以下、数値以外は開始できない |
| 初期値 | 濁音・半濁音有効、3ターン、30秒、10秒、ターンスキップになっている |
| 対戦モード | 個人戦とチーム戦を切り替えられ、初期値は個人戦である |
| チーム設定 | チーム戦で親がチーム数を設定でき、参加者が自分の所属チームを選択できる。チーム名は設定しない。全チームに1人以上の所属が必要で、所属人数0人のチームがある場合は開始できない |
| チーム均等配置 | 未所属者のランダム配置で、既所属者を変更せず各チームの人数差が1以内になる |
| 強制スキップ設定 | 時間切れ時の強制スキップを有効・無効にでき、初期値は無効である |
| エクストラ設定 | 初期状態は折りたたまれ、最小文字数・最大文字数を制限なしまたは1以上の整数で設定できる。最小値が最大値を超える設定では開始できない |
| 終了条件 | ターン数とビンゴ数を切り替えられ、選択中の目標値だけ入力できる |
| 専用URL | ロビー作成後に`/game/:roomId`へ遷移し、ゲーム中もルートURLへ戻らない |
| URL直接接続 | 専用URLを直接開いて名前を入力するとロビーへ参加できる |
| 存在しないURL | 存在しない専用URLでは参加者名入力を表示せず、ルーム不存在メッセージとトップページへの戻るボタンを表示する |
| ロビー開始 | 親がロビーからURLをコピーでき、参加者が2人以上のとき「ゲームを開始」で対戦画面へ進む |
| ロビー設定変更 | 親がロビーでルールを変更して「設定を反映」を実行でき、参加者全員の表示と次のゲームに反映される |
| 親変更 | ロビーで現在の親が接続中の参加者を選択して親を変更でき、元の親は通常の参加者になり、全参加者へ通知される |
| ロビー切断 | ロビーのSSE切断後30分以内なら同じCookieで復帰でき、30分を過ぎるとプレイヤーが削除される。親削除時は残存プレイヤーへ即時に親が移譲され、0人なら部屋が削除される |
| 結果画面切断 | 結果画面の切断後30分以内なら同じCookieで復帰でき、30分を過ぎると参加者が削除される。確定済みの結果情報は親のロビー復帰まで保持される |
| 24時間強制削除 | フェーズ（playing含む）や接続の有無にかかわらず、作成または最終更新から24時間が経過したルームはサーバーにより強制削除される |

## 13.3 カード生成

| 確認項目 | 受入基準 |
| --- | --- |
| サイズ | 指定した奇数`N`に対して各カードが`N×N`のマスになる。5を指定した場合は5×5の25マスになる |
| フリーマス | 全カードの中央マスが同じ清音で、開始時から開いている |
| 中央座標 | `N`に対して行・列が`floor(N / 2)`になる |
| フリーマス候補 | `ん・ゐ・ゑ・ゔ・を`が選ばれない |
| 重複 | フリーマスを含め、同じカード内で同じ文字が複数回出現しない |
| カード間の重複 | 別のプレイヤーのカードでは同じ文字が出現してよい |
| 候補不足 | 有効な文字候補数がカード総マス数未満の設定では開始できない |
| カードサイズ上限 | カードサイズの上限が、候補文字数`M`に対する`N×N <= M`を満たす最大の奇数として計算される |
| オプション | 有効にした文字カテゴリだけが中央以外のカード候補へ追加される |
| 除外文字 | 設定で無効にした文字がカードへ存在しないことがあるが、入力は禁止されない |
| 順序 | カードが登録順ではなくランダムなしりとり順で並ぶ |
| チームカード | 個人戦ではプレイヤーごと、チーム戦ではチームごとにカードが1枚生成される |
| チーム状態 | チーム戦ではカード、手番、順位、ビンゴ数、開放マス数、失格状態をチーム単位で管理し、プレイヤー個人には持たせない |

## 13.4 しりとり判定

次の入力を手動で確認する。

| 入力例 | 期待結果 |
| --- | --- |
| `しりとり` → `りんご` | 有効 |
| `しりとり` → `なし` | 無効 |
| `りんご` → `ごはん` | `ん`で終わるため無効 |
| `くいず` → `すいか` → `がす` | 濁点の付け外しを許可して有効 |
| `きしゃ` → `やきゅう` | 拗音を直音へ変換して有効 |
| `ぎたー` → `たいや` | 伸ばし棒の直前文字から開始して有効 |
| `らーー` → `らっぱ` | 連続する伸ばし棒をさかのぼって`ら`から開始して有効 |
| `きょーー` → `よる` | 伸ばし棒をさかのぼり拗音を直音変換して`よ`から開始して有効 |
| `きゃっ` → `つ`から始まる単語 | 拗音・促音を処理して有効 |
| `まぁ` → `あ`から始まる単語 | 小さいあ行を直音へ変換して有効 |
| 単語途中の`ん` | 有効にできる |
| 既出単語 | 無効 |
| 空文字での確定操作 | フロントエンドで送信が阻止され、手番も消化しない |
| 漢字・カタカナ・英数字を含む入力 | 入力欄へ入力できるが、確定時に送信されず手番も消化しない |
| 伸ばし棒設定が無効な状態の`ー` | 入力可能。カードに`ー`がなければ開放なし |
| 文字数制限 | 最小値・最大値は境界値を含み、範囲外の単語は設定されたターンスキップまたは失格になる。設定画面の展開状態にかかわらず対戦画面に現在の文字数が表示される |

## 13.5 カード開放とビンゴ

- 有効単語に含まれる文字と完全一致するマスだけが全カードで開く。
- `かーど`で`か・ー・ど`だけが開き、`と`は開かない。
- 清音の`か`で濁音の`が`は開かない。
- 同じカード内では文字が重複せず、入力文字に一致するマスがカードごとに最大1つ開く。
- 1単語で複数列が成立した場合、ビンゴ数がすべて加算される。
- 横`N`、縦`N`、斜め2の計`2N+2`列を判定する。
- フリーマスを含む中央列・行・斜めが開始時から判定対象になる。
- 対戦画面で成立列の色・模様が変わり、名前の横のビンゴ数が更新される。
- 対戦画面であと1マスで成立する未開放マスがリーチ表示され、複数列を同時に完成できるマスが追加強調される。

## 13.6 ターン、時間、無効入力

- プレイヤー順がゲーム中に変わらない。
- 有効入力、ターンスキップ、失格のいずれも手番を1回消化する。
- 単語入力の有効・無効、無効理由、ターンスキップまたは失格の処理結果が、全参加者の画面に表示される。
- ターンスキップ後に開始文字が変わらない。
- 失格者が次のターン以降の手番から除外される。
- 1ターン目の1人目だけエクストラタイムが付く。
- 残り時間が0秒になっても自動失格・自動スキップされない。

- プレイヤー順がゲーム中に変わらない。
- 有効入力、ターンスキップ、失格のいずれも手番を1回消化する。
- 単語入力の有効・無効、無効理由、ターンスキップまたは失格の処理結果が、全参加者の画面に表示される。
- ターンスキップ後に開始文字が変わらない。
- 失格者が次のターン以降の手番から除外される。
- 1ターン目の1人目だけエクストラタイムが付く。
- 残り時間が0秒になっても自動失格・自動スキップされない。
- 強制スキップが有効な場合、残り時間0秒で入力途中の内容を破棄して手番が1回だけ自動スキップされる。
- 強制スキップが有効な場合でも、時間切れ以外のカード、開始文字、単語履歴は変更されない。
- チーム戦ではチームの手番中に所属者全員が単語を入力・確定でき、他チームの所属者は確定できない。
- チーム戦ではチームごとにカードとビンゴ数が表示され、チーム単位で終了条件と順位を判定する。
- 対戦中の切断プレイヤーは削除・自動スキップ・自動失格されず、結果状態へ移るまで再接続できる。親の全接続が切断された場合は、接続中の参加者へ即時に親が移譲される。
- SSE再接続後は差分ではなく最新の公開用GameState全体を受信する。
- 明示的なスキップ・失格操作は親が現在手番の対象に対してのみ実行でき、手番外のプレイヤーや他の参加者からは拒否される。
- 指定ターン数の終了は現在ターンを完了してから結果画面を表示する。
- 指定ビンゴ数の到達は現在ターンを完了してから結果画面を表示する。
- 全員失格時は現在のターンの完了を待たず即時で結果画面を表示し、親のゲーム終了操作後も部屋を維持してロビーへ戻る。
- 指定ビンゴ数は`1〜2N+2`の範囲に制限される。
- 順位は Standard Competition Ranking（1224方式）で計算され、同順位がある場合は次の順位をスキップして表示する。

## 13.7 undo

- 有効単語確定後にundoすると、単語、開放マス、ビンゴ数、開始文字、手番が戻る。
- ターンスキップ後にundoすると、スキップ前のプレイヤーが再び手番になる。
- 失格処理後にundoすると、失格状態が解除される。
- undo後の復元対象プレイヤーの制限時間が設定値へリセットされる。
- ゲーム終了後は結果画面を表示し、親がゲーム終了を押すまで結果を確認できる。結果画面からundoは実行できない。
- undo後に既出単語から取り消した単語が除外され、再入力できる。

## 13.8 終了後のロビー

- ゲーム終了後もルームURLと参加者名を維持する。
- ロビーでルールを変更して保存できる。
- 次のゲーム開始時にカード、手番順、フリーマス、単語履歴を新規生成する。

## 13.9 安全性と互換性

- `<script>`やHTMLタグを含む名前・単語を入力しても、画面上でHTMLとして実行されない。
- PC、Android、iOS/iPadOSの各対象端末で設定、対戦、結果の全画面が操作できる。
- `localStorage`の破損値があっても、初期設定画面が表示される。
- 画面全体に M PLUS 1 フォントが適用されており、外部CDNへのフォントリクエストが発生しないこと（バンドル配信されていること）。
