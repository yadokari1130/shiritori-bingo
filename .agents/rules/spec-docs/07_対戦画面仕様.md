# 7. 対戦画面仕様

## 7.1 画面構成

対戦画面には次の情報を表示する。

- ゲーム名・ルームID
- 現在のターン番号と総ターン数または選択中の終了条件
- 現在プレイヤーの名前
- 現在の対戦モードと、チーム戦の場合の所属チーム
- 現在の開始文字
- 残り制限時間（サーバー配信値）
- 単語入力欄（現在の手番プレイヤーまたは現在チームのメンバーのみ表示・操作可能）
- 確定ボタン（現在の手番プレイヤーまたは現在チームのメンバーのみ表示・操作可能）
- undoボタン（親のみ表示・操作可能）
- 無効入力時のエラーまたは処理結果（全参加者に表示）
- 固定されたしりとり順
- 全プレイヤーまたはチームのカード
- プレイヤーまたはチームの横に表示するビンゴ数
- これまでの有効単語履歴

### 親と参加者の表示差分

| 要素 | 親 | 参加者 |
| --- | --- | --- |
| 単語入力欄 | 現在の手番なら表示・操作可能 | 現在の手番または所属チームの手番なら表示・操作可能 |
| 確定ボタン | 現在の手番なら表示・操作可能 | 現在の手番または所属チームの手番なら表示・操作可能 |
| undoボタン | 表示・操作可能（対戦中のみ） | 非表示 |
| スキップ/失格選択 | 現在の手番に対してのみ表示・操作可能 | 非表示 |
| カード表示 | 全員分表示 | 全員分表示 |
| 開始文字 | 表示 | 表示 |
| 制限時間 | 表示 | 表示 |
| 単語履歴 | 表示 | 表示 |

## 7.2 カードの並び順

カードは登録順ではなく、ゲーム開始時に決定したしりとりの手番順で表示する。チーム戦ではチーム順で表示し、カード見出しに所属メンバーを表示する。カード内の行・列の順は変更しない。

カード数が画面幅に収まらない場合は、画面サイズに応じてレイアウトを変更する。

- PC（768px以上）：複数列のグリッドまたは横方向のスクロールを使用する。
- スマートフォン（767px以下）：縦に積み重ねて表示する。各カードは画面幅いっぱいに表示する。

カードの文字とビンゴ状態を確認できることを優先する。

## 7.3 現在手番の表示

現在のプレイヤーまたはチームを強調表示し、次の入力に必要な開始文字を大きく表示する。最初の手番では、フリーマスと同じ開始文字であることを表示する。チーム戦では、現在チームの所属者全員が入力できることを表示する。

手番が終わると、次の対象プレイヤーへ表示を移す。失格者は手番順の表示に残すが、状態を失格として表示し、以降の手番対象から除外する。

## 7.4 単語入力

1. 現在の手番プレイヤーが入力欄へ単語を入力する。
2. 入力中はフロントエンド側でカード上の一致する未開放マスをプレビュー表示する。
3. 現在の手番プレイヤーが確定ボタンを押す、または入力欄でEnterキーを押す。スマートフォンでは、仮想キーボードの「完了」「改行」ボタンでも確定できるようにする。
4. フロントエンドは入力欄の内容を検査する。空文字（0文字）またはひらがなと伸ばし棒`ー`以外を含む場合は、常に固定エラーを表示し、確定APIを呼び出さない（送信を阻止する）。
   - 「入力文字チェック」が有効（デフォルト）の場合：文字数制限、既出単語、しりとり接続、語尾「ん」もフロントエンドで検証し、違反時は固定エラーを表示して送信を阻止する。
   - 「入力文字チェック」が無効の場合：空文字およびひらがな・伸ばし棒以外のみ阻止し、ルール上の無効単語（接続不一致、既出単語、「ん」終わり等）も送信を許可する。
5. 送信可能な場合、フロントエンドは単語をサーバーの確定APIへPOST送信する。
6. サーバーで形式判定およびゲームルール判定（文字数、既出、しりとり接続、語尾）を行う。
7. 有効ならサーバーは全カードを開放し、履歴、ビンゴ数、開始文字を更新する。
8. ゲームルール上の無効入力なら、サーバーは設定に応じてターンスキップまたは失格を自動適用する。入力結果と無効理由、適用した処理結果は全参加者に表示する。
9. サーバーは更新後のゲーム状態をSSEで全接続クライアントへブロードキャストする。
10. フロントエンドは受信した状態で画面を更新し、処理済みの入力欄を空にする。

単語の存在確認は行わない。手番のプレイヤーが単語の妥当性を判断するため、画面には「単語の存在確認は行いません」という説明を表示する。

### スマートフォン入力時の配慮

- 入力欄は画面下部に固定し、ソフトウェアキーボード表示時も操作しやすい位置に保つ。
- 入力欄にフォーカスした際、画面が自動的に入力欄までスクロールするようにする。
- 確定ボタンは入力欄の近くに配置し、親指でも押しやすいサイズ（最小44×44px）とする。

### 通信エラー時の表示

- サーバーへのPOST送信が失敗した場合、エラーメッセージを表示し、入力欄の内容は保持する。
- 対戦中のSSE接続が切断された場合は、ゲームが結果状態へ移るまで再接続を試行する。切断中のプレイヤーを自動スキップまたは失格にせず、再接続成功後に最新状態を受信して画面を更新する。
- ロビーまたは結果画面のSSE接続が切断された場合は30分間再接続を受け付ける。30分以内に再接続できない場合は、そのプレイヤーを該当状態の参加者から削除する。結果状態では確定済みのResultSnapshotを保持する。

## 7.5 制限時間表示

- 手番開始時にサーバーから配信されるremainingTimeMsを表示する。
- 1ターン目の1人目は、通常時間とエクストラタイムの合計を表示する。
- 残り時間はフロントエンド側で秒単位で減少させるが、ゲーム状態の信頼源はサーバーからのSSE配信とする。
- 強制スキップが無効なら、0秒になった後も入力欄と確定ボタンを有効にする。0秒表示は警告色に変えるが、時間切れだけでは手番を終了させない。
- 強制スキップが有効なら、0秒到達時に入力欄と確定ボタンを無効化し、入力途中の内容を破棄して「時間切れでスキップしました」と全員に表示する。
- undoでは、サーバーが復元された手番のremainingTimeMsを開始時設定値へリセットして配信する。1ターン目の1人目ではエクストラタイムも含める。

## 7.6 カードの状態表示

- 未開放マスと開放済みマスを背景色、境界線、文字の太さで区別する。
- 入力中のプレビュー対象は、開放済みとは別の一時ハイライトで表示する。
- ビンゴ成立列は、列全体に共通する色または装飾を付ける。
- リーチマスは未開放のまま、ビンゴ成立列とは異なる背景、境界線、アイコンなどで表示する。複数列を同時に完成できるマスにはリーチ強調を追加する。
- 色だけに依存せず、成立列にアイコン、模様、境界線などを追加する。
- プレイヤー名の横に現在のビンゴ数を表示する。
- 切断中のプレイヤーは、プレイヤー名の横に切断マークを表示する。チーム戦ではカード見出しに表示する所属メンバー名の横にも表示する。
- チーム戦ではチームごとにビンゴ数を表示し、所属メンバーをカード見出しに表示する。
- 失格したプレイヤーまたはチームはカードと名前を残し、失格ラベルを表示する。

### スマートフォンでのカード表示

- カード1枚あたりのマスサイズは、画面幅に応じて可変とし、最低でも読みやすいサイズ（例：5×5カードで画面幅の18%〜20%程度）を確保する。
- カード同士の余白を適切に確保し、タップでの操作ミスを防ぐ。
- プレイヤー名とビンゴ数はカード上部に見出しとして表示し、スクロール時も追従しない。

## 7.7 undo

undoボタンは、直前の確定操作が存在する場合だけ有効にする。対象は直前の有効単語確定、ターンスキップ、失格処理のいずれか1件とする。

undoを実行すると、フロントエンドはundoリクエストをサーバーへPOST送信する。サーバーは次の状態を操作前へ戻し、更新後の状態をSSEで全クライアントへ配信する。制限時間だけは、復元対象の手番の開始時設定へリセットする。

- 現在プレイヤー
- ターン番号と手番位置
- 現在の開始文字
- 有効単語履歴と既出単語集合
- 全プレイヤーの全マス状態
- ビンゴ成立列とビンゴ数
- 失格状態
- 復元対象の手番の制限時間を開始時設定値へリセット

対戦中に直前の確定操作を取り消すことができるが、終了条件を満たして結果画面へ移行した後はundoを実行できない。結果画面では親が「ゲーム終了」を押した後に同じルームのロビーへ戻る。

## 7.8 操作後の通知

有効単語の場合は、開いたマス数と新たに成立したビンゴ列を短時間、全参加者に表示する。ターンスキップの場合は、無効理由と開始文字が変わらないことを全参加者に表示する。失格の場合は、無効理由と以降の手番から除外されたことを全参加者に表示する。
