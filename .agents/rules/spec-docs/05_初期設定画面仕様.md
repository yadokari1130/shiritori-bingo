# 5. 初期設定画面仕様

## 5.1 画面の目的

ルーム作成後のロビーで、親がゲームルールを設定する。参加人数と参加者名は事前に設定せず、参加者が共有URLのロビーでそれぞれ入力する。ルール設定はゲーム開始時に確定し、ゲーム中は変更できない。

## 5.1.1 トップ画面

トップ画面は、全ユーザーが最初にアクセスする画面である。

| 項目 | 内容 |
| --- | --- |
| ルームを作成 | 選択中または編集中の設定および任意のパスワード（合言葉）で新しいゲームルームを作成し、ロビーへ遷移する。親が選択する。 |
| ルームに参加 | 既存のルームIDまたはURLを入力して参加する。パスワードが設定されている場合はパスワードを入力する。参加者が選択する。 |

トップ画面では、利用者の操作やゲームルールの理解に必要な案内だけを、短く自然な日本語で表示する。保存先や保存対象外のデータなど、内部の管理方法を説明する文言は表示しない。見出しやボタンで伝わる操作を、補足文で重ねて説明しない。

画面はVue 3のコンポーネントで構築し、設定プリセットの操作もVueの状態管理とイベント処理で行う。

### ルーム作成フロー

1. 親が「ルームを作成」画面でルール設定を確認・編集し、必要に応じて合言葉・パスワードを入力する（空欄の場合はパスワードなし）。
2. 「ルームを作成」を選択し、サーバーへルーム作成リクエストを送信する。
3. サーバーがルームIDを発行し、パスワードが指定されている場合はbcryptハッシュ化して保存し、`setup`状態の空ロビーを作成する。
4. フロントエンドは専用URL（`/game/:roomId`）のロビーを表示する。
5. 親（部屋作成者）はパスワードの再入力不要で自分の名前を入力して参加し、ロビーでルール設定を変更して反映する。
6. 親はロビーに表示されたURLを参加者へ共有する（パスワードが設定されている場合は合言葉も参加者へ共有する）。
7. 参加者が2人以上揃ったら、親がロビーの「ゲームを開始」を押す。

### ルーム参加フロー

1. 参加者が共有された専用URLを開く、またはトップ画面でURL・ルームIDを指定する。
2. ロビーで自分の名前を入力する。
3. パスワードが設定されている場合はパスワードも入力する。
4. サーバーに参加リクエストを送信し、ロビーの参加者一覧へ追加する。
5. ロビーの状態をSSEで受信し、親がゲームを開始するまで待機する。
6. ゲーム開始後、現在の手番ではない参加者は対戦画面で表示のみ行う。現在の手番プレイヤーは単語入力と確定操作を行える。

## 5.2 ロビー参加者設定

| 項目 | 仕様 |
| --- | --- |
| 参加人数 | 事前設定しない。ゲーム開始時に合計2人以上（人間2人以上、または人間1人＋CPU1人以上）の参加が必要 |
| 名前 | ロビーで参加者ごとに1つのテキスト入力欄から設定する |
| 名前のバリデーション | 空文字は許可しない。重複、文字数、使用文字の制限は設けない |
| CPUプレイヤー | 親は「🤖 CPUプレイヤーを追加」ボタンからCPUプレイヤーを追加でき、キックボタンで個別に削除できる。また、CPUが存在する場合は「🗑️ CPUを一括削除」ボタンで全CPUを一括削除できる。参加者一覧で `🤖 CPU` バッジが表示される |

現在の親はロビーで接続中の参加者を選択して親を変更できる（CPUへの親移譲は不可）。変更後は元の親を通常の参加者として扱い、親の変更結果を全参加者へ通知する。親が切断した場合は、接続中の参加者（人間）のうち参加登録順で先頭の参加者へ即時に親を移譲する。

参加者はロビーで自分の名前を変更できる。変更欄には現在の名前を表示し、空文字では保存できない。名前の変更はゲーム開始前の`setup`状態でのみ行え、変更後の名前を参加者一覧へ反映し、全参加者へ通知する。ゲーム中および結果画面では名前を変更できない。

## 5.3 対戦モード設定

| 項目 | 初期値 | 仕様 |
| --- | --- | --- |
| 対戦モード | 個人戦 | 個人戦またはチーム戦を選択する |
| チーム数 | 2 | チーム戦で使用する2以上の整数。ゲーム開始時に参加者数を超えている場合は開始できない |

個人戦ではチーム設定を表示せず、参加者ごとにカードを1枚生成する。チーム戦ではチーム数に応じた所属チームを表示し、各参加者が自分で所属先を選択する。チーム名は設定しない。

親には、未所属の参加者だけをチーム間の人数差が1以内になるようランダムに割り当てる「未所属者を均等に振り分ける」ボタンを表示する。参加者が2人以上で、チーム数が参加者数以下かつ全チームに1人以上が所属する場合にゲームを開始できる。未所属者が残っていても、ゲーム開始時に同じ均等ランダム配置をサーバーで行うが、配置後に所属人数が0人のチームが存在する場合は開始できない。

## 5.4 カード設定

### カードサイズ

カードサイズは3以上の奇数を指定する。数値入力欄は初期値5、最小値3、増減幅2とし、選択したカード文字候補数から算出した最大値まで入力できるようにする。最大カードサイズは、候補文字数を`M`としたとき、`N×N <= M`を満たす最大の奇数`N`とする。偶数、2以下、最大値超過、数値以外の値ではゲームを開始できない。

カードサイズ`N`を指定した場合、カードは`N×N`となり、中央の座標は`floor(N / 2)`行・`floor(N / 2)`列になる。設定変更時に、カードのマス数とビンゴ列数を固定値で表示せず、指定サイズから説明する。

フリーマスを含めて同じカード内で文字を重複させない。有効なカード文字候補数が`N×N`未満になる設定ではゲームを開始できない。カードサイズの入力欄には、現在の候補数から算出した最大値を表示する。

### カード文字設定

カードの中央以外のマスに含める文字カテゴリをチェックボックスで設定する。

| 項目 | 初期値 | カード候補に追加する文字 |
| --- | --- | --- |
| 拗音 | 無効 | `ゃゅょ` |
| 促音 | 無効 | `っ` |
| 伸ばし棒 | 無効 | `ー` |
| 小さいあ行 | 無効 | `ぁぃぅぇぉ` |
| 濁音 | 有効 | `がぎぐげござじずぜぞだぢづでどばびぶべぼ` |
| 半濁音 | 有効 | `ぱぴぷぺぽ` |

基本の清音は常にカード候補へ含める。`ん・ゐ・ゑ・ゔ・を`は、どの設定でもカード候補へ含めない。

設定で無効にした文字カテゴリも、単語入力としりとり判定では使用できる。伸ばし棒は設定が無効でも入力できる。

## 5.5 終了条件設定

終了条件はラジオボタンで1つだけ選択する。

| 項目 | 初期値 | 関連入力 |
| --- | --- | --- |
| 指定ターン数 | 選択 | ターン数。初期値3 |
| 指定ビンゴ数 | 未選択 | ビンゴ数。初期値3 |

選択した終了条件に対応する数値入力欄だけを有効にする。ターン数は正の整数として扱い、ビンゴ数は`1`以上`2N+2`以下の整数として扱う。`N`はカードサイズである。

## 5.6 時間設定

| 項目 | 初期値 | 仕様 |
| --- | --- | --- |
| 1人あたりの制限時間 | 30秒 | 手番開始からの時間 |
| 初回エクストラタイム | 10秒 | 1ターン目の1人目だけに加算 |
| 時間切れ時に強制スキップ | 無効 | 有効時は0秒到達で入力途中の内容を破棄し、手番を自動的にスキップする |

強制スキップが無効の場合は、時間が0秒になっても自動的に失格またはスキップしないことを画面上で説明する。有効の場合は、時間切れで手番が自動的に終了することを説明する。

## 5.7 無効入力設定

| 項目 | 初期値 | 内容 |
| --- | --- | --- |
| ターンスキップ | 選択 | 無効入力後に手番だけを終える |
| 失格 | 未選択 | 無効入力後にプレイヤーを以降の手番から除外する |

ゲームルール上の無効入力には、選択した設定をサーバーが自動適用する。親が手動でスキップまたは失格を実行する操作を用意する場合、その操作は現在手番のプレイヤーまたはチームに対してのみ親が行える。手番外のプレイヤーに対する手動スキップ・失格は行えない。

## 5.8 エクストラ設定（エクストラルール）

エクストラ設定（エクストラルール）は展開可能な項目として表示し、初期状態では折りたたむ。次の項目を設定できる。

| 項目 | 初期値 | 仕様 |
| --- | --- | --- |
| 入力文字チェック | 有効 | チェックボックス。有効時はフロントエンドでしりとり接続・文字数・既出単語・語尾「ん」を検証して無効単語の送信を防止する。無効時は送信を許可し、無効単語はサーバー判定により即座にターンスキップまたは失格となる。 |
| 最小文字数 | 制限なし | 1以上の整数。指定値未満の単語を無効入力とする |
| 最大文字数 | 制限なし | 1以上の整数。指定値を超える単語を無効入力とする |

最小文字数と最大文字数は境界値を含む。両方を指定する場合は、最小文字数を最大文字数以下にする。範囲外の単語は「無効入力の扱い」に従ってターンスキップまたは失格とする。対戦画面では、エクストラ設定の展開状態にかかわらず、入力欄に現在の文字数を表示する。

## 5.9 名前付き設定プリセット

設定は編集中の一時状態として扱い、設定変更時、ロビー作成時、ゲーム開始時には自動保存しない。利用者が「プリセットを保存」を実行した場合だけ、次の情報を`localStorage`へ保存する。

```text
Preset
├── id: string
├── name: string
├── settings: Settings
├── createdAt: number
└── updatedAt: number
```

`settings`には次のゲームルール設定を含める。

- カードサイズ
- 対戦モードとチーム数
- カード文字カテゴリ
- 終了条件と目標値
- 制限時間とエクストラタイム
- 時間切れ時の強制スキップ
- 無効入力の扱い
- エクストラ設定（入力文字チェック、最小文字数、最大文字数）

プリセット一覧から、プリセットの選択、読み込み、上書き保存、削除を行える。参加者名、参加人数、ルームID、カード、開いたマス、単語履歴、現在の手番はプリセットに含めない。ゲーム進行状態はサーバーのSQLiteから取得し、専用URLを再読み込みした場合は再接続Cookieで同じ参加者として最新状態へ復帰する。保存データの旧形式との互換性は扱わない。

保存値が読み込めない場合は該当プリセットを読み込まず、初期値を表示する。保存機能が利用できない場合はゲーム自体を妨げず、プリセットを保存できない旨を通知する。

## 5.10 開始操作

トップ画面で「ルームを作成」を押すと、次の処理を行う。

1. 選択中または編集中のルール設定をサーバーのルーム作成APIへPOST送信する。
2. サーバーがルームIDを発行し、参加者が未登録の`setup`状態で初期化する。
3. フロントエンドは専用URLのロビーを表示し、URLコピー手段を提供する。
4. 親がロビーでルール設定を変更した場合、「設定を反映」で設定更新APIを実行する。
5. ロビーで2人以上が参加した状態で親が「ゲームを開始」を押す。
6. サーバーが参加者名、プレイヤー順、フリーマス、全カードを新規生成し、SSEで`playing`状態を配信する。

ロビーで表示中の設定をゲーム中に変更しても、現在のゲームには反映しない。
